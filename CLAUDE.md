# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

This repo is a sandbox for trying out the Claude Code GitHub Actions integration. It holds two independent projects:

- `pos-demo/`: **StoreLite POS**, a portfolio app with Spring Boot microservices, React, and RabbitMQ (see below).
- The Python package `shopcart` at the repo root, a deliberately small sample with **intentional bugs**, each tracked as a GitHub issue (#2–#6). When asked to fix an issue, fix only that issue so the others stay reproducible.

## pos-demo (StoreLite POS)

`pos-demo/SPEC.md` is the spec and `pos-demo/README.md` has the design notes. Run commands from `pos-demo/`:

```bash
make up                 # build + start postgres, rabbitmq, both services, web (http://localhost:5173)
make smoke              # end-to-end check against the running stack (needs curl + jq)
make test               # all tests; Java runs in the maven:3.9-eclipse-temurin-21 image (no local JDK needed)
make test-inventory     # or test-sales / test-web
mvn -f inventory-service/pom.xml test -Dtest=LowStockRuleTest   # single test, if a local JDK 21 is available
cd web && npm test -- src/basket.test.ts                         # single web test
```

Architecture that spans several files:

- **API-first.** `api/*.yaml` is the source of truth. Each service's controller `implements` an interface that `openapi-generator-maven-plugin` generates at build time (`target/generated-sources`, packages `com.storelite.<svc>.api` and `.api.model`). `web/src/api/*.d.ts` is generated by `npm run gen`, is gitignored, and runs automatically before dev, build, and test. To change an endpoint, edit the YAML first, then the code that implements it.
- Generated model names (`Product`, `Sale`, `Alert`, …) are API types. The persistence and domain records are named `*Row` (`ProductRow`, `SaleRow`) and convert with `toApi()`.
- **Events** go through the topic exchange `pos.events` (`api/events.md`): `sale.completed` (sales → inventory) and `stock.low` (inventory → sales). Each service has its own copy of the event records in its `messaging/` package. Producers publish via `ApplicationEventPublisher` and a `@TransactionalEventListener` that sends to RabbitMQ after commit. Consumers are idempotent by `eventId`. The JSON converter uses `setAlwaysConvertToInferredType(true)`, so consumers don't depend on the producer's class names.
- Each service owns a Postgres **schema** (`inventory`, `sales`) in one database and uses Flyway plus `JdbcClient` with plain SQL (no JPA). Always schema-qualify table names.
- sales-service calls inventory-service over REST (`InventoryClient`) at checkout to price the basket. In Compose, sales starts after inventory is healthy, because inventory declares the `sale.completed` queue.
- `src/test/resources/docker-java.properties` pins Docker API 1.44. Testcontainers 1.21 otherwise fails against Docker Engine 29+.
- `web/` must stay on TypeScript 5.x: openapi-typescript needs the TypeScript JS API, which TypeScript 7 removed.

## shopcart commands

```bash
pip install -e '.[dev]'                          # install package + pytest
python -m pytest                                 # run all tests (pythonpath=src is set in pyproject.toml)
python -m pytest tests/test_cart.py::test_add_and_total   # run a single test
```

There is no linter, formatter, or Python CI configured yet (adding pytest CI is issue #6).

## shopcart code layout

- `src/` layout; the package is `src/shopcart/`. `__init__.py` re-exports the public API (`Cart`, `Item`, `apply_discount`, `parse_price`).
- `pricing.py` holds pure price helpers; `cart.py` holds `Item` (dataclass) and `Cart`, and `Cart.total()` delegates discounting to `pricing.apply_discount`, so a pricing fix changes cart totals too.
- Tests construct carts with `Cart([])` rather than `Cart()` to sidestep the shared-mutable-default bug (issue #2). Once that is fixed, tests can use `Cart()`.

## GitHub Actions

- `.github/workflows/claude.yml` runs Claude when `@claude` appears in an issue title/body, issue comment, PR review, or PR review comment.
- `.github/workflows/claude-code-review.yml` runs the `code-review` plugin automatically on every PR and posts inline comments.
- Both authenticate with the `CLAUDE_CODE_OAUTH_TOKEN` repo secret.
- `.github/workflows/pos-ci.yml` builds and tests `pos-demo/` (Maven verify per service, web test + build, then `docker compose build`).
